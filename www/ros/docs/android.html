Coming from Android

Reload OS follows the model you know from Android: a system with a launcher and Settings, apps that are files you install, a Studio with a layout editor and an emulator, and an SDK. The device is an ESP32 touch screen instead of a phone, and the language is C. This page says what each thing you know is called here.

Open Studio Get the app kit

Your first app, step by step

  1. New project. In Studio: New, a template (Starter, Dashboard, Form or Empty) and your board in the toolbar. Nothing to install - Studio runs in the browser.

  2. Lay out the screen. Drag widgets from the Palette, as in the layout editor. A Column or a Row is a LinearLayout; a Free area places each widget by an anchor and an offset.

  3. Wire it up. Where you would write a click listener, pick an event in Attributes › Events: when it is tapped, open a screen, set another widget's text, show a dialog. For logic of your own choose Call a function and write it in app.c.

  4. Run. Run is the emulator: the device's real interface code in the browser, the mouse as a finger, Esc as the back gesture.

  5. Build. Sign in and choose Export › ELF - the app is built on our server and comes back as one .elf file, your APK. Or Export › Project folder and build it yourself with the app kit: ./build.sh myapp.

  6. Install. Copy the file into apps/ on the device: open http://<device>/files in a browser (Settings › Remote desktop on the device shows the address and the login), or plug the device into a PC as a USB drive, or use an SD card. Restart the device and tap the new tile.

The same screen, twice

A button that changes a text. On Android:

class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.main)
        findViewById<Button>(R.id.save).setOnClickListener {
            findViewById<TextView>(R.id.status).text = "Saved"
        }
    }
}

On Reload OS the layout is Studio's ui.c, and this is all of your app.c besides the lines Studio writes for the launcher's tile. In Studio the button's event is Call a function, on_save - or, with no code at all, Set a text.

#include "ui.h"

void on_save(lv_event_t *e)              /* the button's event */
{
    lv_label_set_text(ui.status, "Saved");
}

static void create(lv_obj_t *body)       /* onCreate(): the first screen */
{
    ui_start(body);
}

static void destroy(void)                /* onDestroy() */
{
    ui_stop();
}

What is different

The device is a microcontroller, not a phone. These are the habits to change; the guide's rules have the details.

  • One process, no sandbox. An app runs inside the firmware with its full rights. There are no permissions to ask for, and a crash in an app restarts the device.
  • The main-thread rule is stricter. As on Android, nothing slow on the interface's task: no network, files or serial lines there. Android says the app isn't responding; here a screen that does not respond for 60 s restarts the device.
  • Memory is counted in megabytes. About 100 KB of the fast internal RAM is free; big buffers come from PSRAM.
  • Nothing runs in the background. When the app closes, its tasks end: count them, and end each with ros_task_end().
  • The screen is the board's. One size a board, from 320×480 to 1280×800, mounted either way round: ROS_SCR_W, ROS_SCR_H and ROS_PORTRAIT say which.
  • Turning the screen or changing the theme closes the app and builds its screen again - an activity recreated, without a saved state.
  • Only what the firmware exports. api.txt is the whole SDK; double is not in it - use float or integers.

What Android has and Reload OS does not yet

Installing on the device from Studio in one step, a log window, string resources for several languages, an app store, and signed apps. If you miss one of them, tell Reloader.
